# ADR-0005: Identifiers: device-generated UUIDv7; readable references; company code TH-ZM-nnnnnn

**Status:** Accepted (26 November 2026)
**Source:** R-09, R-16 in [../engineering/recommendations.md](../engineering/recommendations.md)

## Context
Offline tablets must create records without contacting the server. People need short references they can read out on the phone. The approved rule is that the permanent company code is generated, never chosen.

## Decision
- Every entity's primary key is a **UUIDv7**, generated by the application or the device. It is time-ordered, so it is index-friendly.
- Human-readable references are separate fields, assigned by the server: e.g. registration `REG-2026-000145` (assigned on first sync).
- The **company code** is `TH-ZM-` plus a 6-digit zero-padded number from a PostgreSQL sequence (e.g. `TH-ZM-000123`), assigned only on approval. It never changes, including on ownership transfer.
- Clients never supply a company code. The temporary `POST /api/v1/companies` endpoint with a caller-supplied code is removed in Release 1.

## Consequences
Offline capture works without ID clashes. Gaps in the sequence (from rolled-back transactions) are acceptable and documented.
